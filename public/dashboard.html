Authentication Workflow

Architecture
1

Credential Verification

Client submits credentials over POST. The backend normalizes email and performs bcrypt hash verification with timing-attack prevention.

2

Session Fixation Immunity

Upon successful verification, req.session.regenerate() issues a completely fresh session identifier, destroying pre-auth tokens.

3

Persistent File Storage

The user session payload is serialized into data/sessions/ using session-file-store with automatic TTL expiration.

4

HttpOnly Cookie Issuance

A signed cookie (codeorbit.sid) is attached with HttpOnly, SameSite: Lax, and Secure flags.

5

Server-Enforced Authorization

Protected routes validate sessions on the server. Aggressive Cache-Control: no-store headers prevent browser back-button caching.

Security Controls Audit

Verified
  • Bcrypt 12-Round Password Hashing: Passwords are one-way hashed with cryptographically strong salt before saving.
  • Zero Plaintext Storage: Passwords never exist in plaintext, even temporarily in memory or storage logs.
  • Anti-Brute Force Rate Limiting: Login attempts are capped at 5 per 15-minute window per IP using express-rate-limit.
  • Generic Error Disclosures: Login failures return generic 401 messages to prevent user enumeration attacks.
  • Safe Projection Filtering: API endpoints strictly filter out passwordHash from all response payloads.
  • Cache-Control No-Store Protection: Authenticated views prevent browser disk caching to block back-button page retrieval after logout.
